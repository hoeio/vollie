# Runtime knobs of the patched CPU module

Environment variables read by `ggml_graph_compute` before every graph, so an app can change them
between generations (`setenv`; `runtime/dart` has setters) without reloading the model. Unset or 0
means stock behaviour, except for the knobs marked default on below (`GGML_MMID`, `GGML_Q3K_X4`, `GGML_Q3K_ILP`, `GGML_SSM_INPLACE`, `GGML_CONV_RING`), where `0` switches them off. None changes results; each was checked bit-identical with
`llama-perplexity` at `-ub 1`, `-ub 32` and `-b 512`.

| variable | values | effect | measured |
|---|---|---|---|
| `GGML_TINY_OP` | elements, e.g. `65536` | ops with at most this many elements (in output and inputs; GET_ROWS by output) run on thread 0 alone; syncs between consecutive such ops are skipped. Mat-muls, SSM scan, flash attention and ops with internal syncs never count as small | SD888 2 threads: 0 → 3.2, 65536 → 7.0 tok/s |
| `GGML_EXPERT_IO` | bit mask | MoE expert reads through mmap: **1** `MADV_WILLNEED` the routed experts of a layer (gate/up/down together) when its first `MUL_MAT_ID` runs; **2** `MADV_RANDOM` on expert tensors (no read-around); **4** helper thread guesses the next layer's experts (its router on this layer's FFN input) and prefetches them; **8** guess 2 more than the model routes to | SD888 3 threads: 0 → 6.1, 1 → 11.8 tok/s; 5 → 12.0 vs 1 → 10.6 in another run; 2 lost; 8 inconclusive |
| `GGML_Q3K_VEC` | `1` (default) / `0`; empty value = on since round 5 (was read as 0; harmless, the x4 kernel bypasses it) | NEON Q3_K dot with vectorized sub-block sums / upstream loop | M4 A/B: expert mat-muls −4..−8% |
| `GGML_CPU_PROF` | `1` / `2` | **1**: thread 0 times every op of one-token graphs (**2**: of 2-8-token graphs, i.e. speculative verify batches; `us/token` is then µs per graph and `tokens=` their total): per op type, count, µs computing, µs waiting at the sync after it; one `cpu-prof` line per 32 graphs on stderr, with `pred=` (share of real experts that were guessed) | |
| `GGML_CPU_AB` | `q3k`, `tiny:<n>` | alternates the setting every one-token graph (A = normal, B = upstream Q3_K loop / threshold `<n>`); with `GGML_CPU_PROF` the stats are split into `ab=A` and `ab=B` lines over the same 64 tokens. Not for `GGML_EXPERT_IO`: one token's prefetch warms the cache for the next | |

Reading a `cpu-prof` line:

```
cpu-prof graphs=32 threads=3 tiny=65536 eio=5 q3k=1 pred=85% us/token=98176 compute=74768 wait=23016 nodes=1963 barriers=818 | MUL_MAT_ID 120:34214+16861 MUL_MAT 265:28518+3364 ...
```

`us/token` is the whole graph; `compute` + `wait` is thread 0's time in ops and at syncs. After `|`,
per op type, sorted by cost: `count per token : µs computing + µs waiting`. A page fault inside a
kernel shows as computing time on the thread that took it; pair the line with major-fault counts
(`/proc/self/stat`) to tell flash reads from arithmetic.

## Round-1 knobs (defaults as stated per knob)

Introduced in app 2.2.6+29 (research kit `r1`; see the campaign report). Off unless marked default on; checked bit-identical at `-ub 1`, `-ub 32`, `-b 512` unless marked otherwise.

| variable | values | effect | status |
|---|---|---|---|
| `GGML_MMID` | bit mask, **default 3** (`''` = unset) | one-token `MUL_MAT_ID`: **1** no barrier inside the op (each thread quantizes the activation row and builds the expert map itself); **2** 32-row chunks claimed dynamically through per-expert counters that thread 0 resets before the preceding barrier (needs 1) | bit-identical; device: with `GGML_Q3K_X4`, −8.3 %/token (R18) |
| `GGML_Q3K_X4` | `1` (**default**), `0` | Q3_K expert rows four at a time sharing the activation loads (`ggml_vec_dot_q3_K_q8_K_x4`) | bit-identical; device: with `GGML_MMID=3`, −8.3 %/token (R18) |
| `GGML_Q3K_KERN` | `1`, default **1** (compiled default since r11, R35); `0` = off | in-register Q3_K x4 expert kernel inside `ggml_vec_dot_q3_K_q8_K_x4` (generated asm, `tools/q3k_kernel/gen_kern.py`); replaces the `_x4_ilp` block loop | bit-identical (2×10⁵ row-quads, PPL chunks 1-3 at three batch settings, greedy 32); bit-identical on device ×4 (R35/R37/R38 greedy text + per-window k̄); device assembly 562 → 377 NEON ops per 4-row block; host ns/row-block 0.74-0.75 of the r9 path, host `MUL_MAT_ID` −0.85 ± 0.05 ms (R34); device cpu-bench new/old 0.742 / 0.724 (R37; that bench ran on the X1, see GGML_CPU_BENCH) and 0.778 / 0.766 on a verified A78 at 2,112 (R41); **device `MUL_MAT_ID` speed claim FALSIFIED under the pre-registered pooled rule, +1.84 ± 4.22 ms/token (R38)** — the kernel stays as an exact change, its speed claim is closed |
| `GGML_EXPERT_SKIP` | permille | an expert whose normalized routing weight is below this is not computed (its rows are zero); `GGML_EXPERT_SKIP_RENORM=1` rescales the remaining weights | **not bit-exact**; host wikitext-2 60 chunks: stock 9.870, 30 → 9.874, 60 → 9.845, 100 → 9.916, 150 (renorm) → 13.63; only ~1% of routed experts fall under 0.06 |
| `GGML_HELPER_CPUS` | `0-3`, `0,1,2,3` | cores for the next-layer expert-guess helper thread (re-read per job; `''` = every core) | device R18: 4 threads + helper on an A55 no better than 3 threads; closed |
| `GGML_REPACK_RELEASE` | `1` (at load) | after a tensor is repacked, `MADV_PAGEOUT` (fallback `MADV_COLD`/`DONTNEED`) its memory-mapped source pages so the page cache can hold experts instead | device R18: inconclusive (noise) |
| `GGML_BARRIER_BENCH` | n | once per distinct value: n empty barriers before the first op of the next one-token graph; prints `cpu-bench barriers=n threads=t us/barrier=x` | measurement |
| `GGML_CPU_BENCH` | `1`, default 0 | once per value, on the first graph: one `cpu-bench q3k threads=1 K=… rows=… old= new= int8= q4x4= scalar= exact_new= exact_int8= exact_scalar= hot= cold= cold_touch= exact_hot= exact_cold= exact_cold_touch= [instrument=ok\|invalid] cpu=<first>-<last> migr=<n> cpu_ok=<n>/21 pinned=<0\|1> mhz=<min>/<max>` line (1-thread ns/row for the old kernel, the new kernel, the int8 reference, the q4 x4 reference and the scalar-assisted prototype; `exact_*` are bit-identity flags). Bench thread pinned to cores 4-6 and re-pinned per shape; a trial is valid only if `sched_getcpu()` is in 4-6 at both ends; cold fields = median of fresh 338-KB slices ≥ 8 MB apart in a 48-MB arena, hot = the same slice re-run at once; `instrument=invalid` on the K 512 line iff cold/hot < 1.05 | host (K 1,536): new/old 0.750, int8/old 0.521, scalar/old 0.708, old/q4x4 3.00 (R34); device R37 (r11, A78 at 2,112 MHz, unpinned, pre-r13 format): new/old 0.742 / 0.724; R40/R41: r12 and r13 benches ran on A78s with stale `cpu=`/`mhz=` labels (read once before any migration); it was the R37 (r11) bench that ran on the X1 (cpu 7, 2,841 MHz): r13b verified-A78 old 201.52 ns/row vs r11 117.49 = 1.715 = 2,841/2,112 × 1.28 IPC. r13b verified (cpu=6-6 migr=0 cpu_ok=21/21 at 2,112): K 1,536 old 201.52 new 156.86 int8 100.30 q4x4 78.58, hot 171.10 cold 178.43 cold_touch 175.78 (cold/hot 1.04); K 512 cold/hot 0.99 — the expert kernel is ≈ 87 % of the in-situ slot (new 68 %) |
| `GGML_MMID_TOUCH` | `1`, default 0 | one volatile demand load of the first byte of each 4-KB page a claimed `MUL_MAT_ID` chunk's expert rows span, after the chunk claim and before the kernel (`MMID=3` path; `prfm` not used) | bit-identical (row-quads 0 differ, PPL chunks 1-3 at three batch settings, greedy 32; host and device r13 ×3); class K on device (majflt B/A 0.929, adv 1.005, R40); device speed: R39 pre-registered band −1.5..−4.5 ms/token on `MUL_MAT_ID`, **PARKED (R41): verified-A78 bench cold/hot 1.04 / 0.99 — the page-latency model was withdrawn (kernel ≈ 87 % of the slot); the ABBA session was not spent; knob stays in the code, default off** |
| `GGML_MMID_FUSE` | `1`, default 0 | gate+up `MUL_MAT_ID` pair + the `SWIGLU` fused in the CPU module: one quantize, one chunk counter per expert, same `vec_dot` and same swiglu per element; `MUL_MAT_ID` ops 120 → 80, `GLU` 116 → 76, nodes 1855 → 1775, barriers 746 → 666 per token (device graph); refuses when Q4 expert copies or the anon cache are active | bit-identical; round 14 item (R42): host identity exact (3,600 fused vs separate slot rows, 0 differing floats; PPL chunks 1-3 identical at -ub 1/32/-b 512, -t 6; greedy 32 identical); host ABBA `MUL_MAT_ID`+`GLU` −0.49 ± 0.12 ms (relative); device pending |
| `GGML_MMID_CHUNK2` | `1`, default 0 | `MMID=3` path claims two chunks per `fetch_add` while ≥ 2·nth remain, one at the tail; kit composite `GGML_CPU_AB=knob:MMID_FUSE+CHUNK2:0:1` | bit-identical; round 14 item (R42): host identity exact (see `GGML_MMID_FUSE`); device pending |
| `GGML_CPU_AB_BAAB` | `1`, default 0 | kit only: A/B blocks after warm-up run B A A B … instead of A B B A (cancels the position-1 fault bias found in r10-r12, R39 / round13_plan §B) | measurement |
| `GGML_MMID_TEST1` | `1`, default 0 | host test only: lets the `MUL_MAT_ID` fast path run at 1 thread so a knob can be class-tested without a fault-around race; the kit never sets it | measurement (R39 amendment) |
| `GGML_CPU_AB` | `knob:NAME:A:B[,NAME:A:B…]` | generic in-generation A/B over TINY_OP, MMID, Q3K_VEC, Q3K_X4, Q3K_ILP, SSM_INPLACE, CONV_RING, EXPERT_SKIP. **ABBA since round 5** (`knob:` mode only): warm-up tokens, then blocks in A B B A order, one `cpu-prof ab= blk=` line per block; the parser reports B − A ± 1σ over post-warm-up blocks | measurement |
| `GGML_CPU_AB_WARM` | tokens, default 16 | warm-up tokens before the first ABBA block | measurement |
| `GGML_CPU_AB_BLOCK` | tokens, default 8 | tokens per ABBA block | measurement |
| `GGML_SSM_INPLACE` | **default on** since round 5 (empty = unset = on), `0` = off | the one-token `SSM_SCAN` writes its new state straight into the recurrent-cache slot; the state `CPY` node is dropped | bit-identical |
| `GGML_CONV_RING` | **default on** since round 6 (empty = unset = on), `0` = off | the one-token `SSM_CONV` reads the old conv state and x in place and shifts the state into the cache itself; the 36 `CONCAT` and 36 conv `CPY` ops are dropped (nodes 1911 → 1839); single sequence, K = 1, d_conv = 4 only, else stock path | bit-identical; host −1.2 ms/token on its own ops (noisy) |
| `GGML_HEAD2` | rows `M` (0 / unset = off) | two-stage output head: a cheap copy (type `GGML_HEAD2_Q`) screens all rows, the top-`M` rows are recomputed exactly from the stock head; default off, bit-identical when off | **not bit-exact**; host wikitext-2 PPL +0.19 % at `GGML_HEAD2_Q=q2_k`, `M`=8,192 (9.6237 vs 9.6051), argmax-identical; `reports/memos/head2stage_fix.md`. Recommended served pair (R31): `GGML_EXPERT_SKIP=117 GGML_HEAD2=2048 GGML_HEAD2_Q=q4_0`, PPL 9.7886 (+1.91 %), head op −1.70 ms device; binary default still off. |
| `GGML_HEAD2_Q` | `q2_k` (code default; q4_0 recommended (R31)) / `q3_k` / `q4_0` / `q4_0_plain` | type of the screening copy made at the first head op; `q4_0` quantises the anon copy to Q4_0 and repacks it 4x4 into `block_q4_0x4` (sdot gemv; copy 86.7 MB; AVX2/SVE hosts keep the plain screen); `q4_0_plain` (test only) is r7's row-major Q4_0 screen | only with `GGML_HEAD2`; default off; `reports/memos/head2stage_fix.md` |
| `GGML_HEAD2_BATCH` | `1` | test only (`llama-perplexity`): the same two-stage head per column at batch > 1, so the full-set gate can be run | only with `GGML_HEAD2`; `reports/memos/head2stage_fix.md` |
| `GGML_MM_CHUNK` | rows per chunk, default 64 | chunk size of the dynamic row split at `nr1 == 1` in `mul_mat` / `mul_mat_id`; the `MMID` no-barrier path uses `MIN(32, n)` | bit-identical at any value; host M4 slower at 16 / 32 (`MUL_MAT` +1.67 / +0.54 ms, R32) (R33: 16 is slower on the device, wait +0.70 / compute +0.74; keep 64) |
| `GGML_EXPERT_Q4_LAYERS` | `n` layers, default 0 | repacked `Q4_0x4` anon copy of the experts of the `n` most-routed layers (quantised from the served file, Q8_0 activations) | **numerics**; full-set gate fails at n = 4 and 2 on top of skip 117 (R32); research only (R33: no device effect inside noise; dead) |

| `GGML_DENSE_WILLNEED` | `1`, default 0 | `MADV_WILLNEED` over the non-expert weights (562.5 MB) once per prompt graph | advice only, bit-identical (R33: no window-1 effect) |
| `VOLLIE_SAMPLER_BYPASS` | `1`, default 0 (llamadart / `libllama.so`, not the CPU module) | exact fast path for the repetition-penalty sampler when the candidates are the full vocabulary in order (plus llamadart's top-k / top-p / temp bypass at temp <= 0); enabled per generation | exact: greedy text identical; sampling 0.43 → 0.10 ms/token host (R32); `patches/llama.cpp/0003-sampler-bypass.patch` (R33: outside-graph 1.90 → 1.13 ms/token on the device, exact; part of the served config; from 2.2.15+38 it is part of the compiled served default, `Research.served`) |
| `GGML_EXPERT_LOG` | `1` | lab: prints the routed expert ids per layer per token (`eid …`) | measurement |

`cpu-prof` lines also carry `head2= head= majflt= minflt=` (head2: ops on the two-stage head; head: head time; majflt / minflt: `getrusage` page faults per profiling window, and per side of an ABBA block in `ab=` lines).

`cpu-prof` lines now carry `x4= mmid= skip=<t>/<share>% mmid_thr=<µs per thread inside MUL_MAT_ID>`.
